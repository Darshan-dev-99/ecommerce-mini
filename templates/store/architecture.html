How a BazaarNoon request works

Every catalogue read is cache-aside: the browser calls the REST API, the API checks the cache first, and only a miss touches the database — after which the result is written back into the cache for the next shopper. The numbers below are read from the live cache, not a mock-up.

Cache-aside in one function

def cache_aside(namespace, payload, producer, ttl):
    value, hit = get_cached(namespace, payload)   # cache.get(key)
    if hit:
        return value, True                        # HIT  → no DB
    value = producer()                            # MISS → SELECT …
    set_cached(namespace, payload, value, ttl)    # cache.set(key, ttl)
    return value, False

Backend is chosen at startup: Redis when REDIS_URL is set, Django's in-process cache otherwise, so the same code runs with or without services.
